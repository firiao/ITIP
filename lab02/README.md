# Лабораторная работа 2. Классы и инкапсуляция

## Цель работы

Научиться описывать собственный тип данных, проверять состояние в конструкторе
и размещать поведение рядом с данными.

## Состав модуля

- `SampleStatus` - enum статусов наблюдения.
- `Identificator` - неизменяемый идентификатор (record).
- `DataSample` - учебный класс наблюдения с инкапсуляцией.
- `BankAccount` - подготовительный класс (счёт).
- `DataSampleTest`, `BankAccountTest` - JUnit-тесты.

## Инварианты класса DataSample

1. `id` не `null` (валидность содержимого гарантирует `Identificator`).
2. `label` не `null` и не пустая строка.
3. `status` не `null`, всегда одно из значений enum `SampleStatus`.
4. `features` не `null` и не пустой массив.
5. Массив `features` защищён **defensive copy**:
   - копируется в конструкторе (`features.clone()`);
   - копируется при возврате из `getFeatures()`.
6. Поля `id`, `label`, `features` объявлены `final`, не меняются после создания.
7. Статус меняется **только** через `changeStatus(SampleStatus)`.

## Инварианты класса Identificator

1. `value` не `null` и не пустая строка.
2. Класс неизменяемый (`record`), `value` не меняется после создания.

## Инварианты класса BankAccount

1. `balance` не может быть отрицательным.
2. `deposit(int)` принимает только положительную сумму.
3. `withdraw(int)` принимает только положительную сумму и не больше текущего баланса.
4. Поле `balance` меняется только через `deposit` / `withdraw`.

## Основные решения

### Инкапсуляция

Поля классов `private`. Сеттеры отсутствуют. Изменение состояния возможно
только через осмысленные публичные методы (`changeStatus`, `deposit`,
`withdraw`), которые проверяют свои аргументы.

### Defensive copy

Массив `features` копируется дважды:

- в конструкторе: чтобы изменения исходного массива снаружи не влияли на объект;
- в `getFeatures()`: чтобы изменения массива, полученного из геттера, не влияли на объект.

Обе проверки покрыты отдельными тестами.

### Identificator как value object

`Identificator` это `record` с одним полем `value`. Два экземпляра с
одинаковым `value` равны и взаимозаменяемы. Record гарантирует
неизменяемость, автоматически предоставляет `equals`, `hashCode`,
`toString`. Валидация выполняется в компактном конструкторе.

### Два уровня валидации идентификатора

- `Identificator` проверяет **содержимое** (`value == null`, `value.isEmpty()`).
- `DataSample` проверяет, что сам объект `Identificator` не `null`.

Это два разных инварианта, оба нужны.
